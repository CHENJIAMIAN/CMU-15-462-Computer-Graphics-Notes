# P11 网格与流形

## 一句话概括

本集从"数字图像为什么用方格"这一熟悉的例子切入，说明曲面应当被理解为局部二维的流形（manifold），给出多边形网格的流形判据，并沿着"三角形汤 → 索引网格 → 关联矩阵 → 半边（half-edge）"的路线讲解网格数据结构的设计取舍，最后落到边翻转、边分割、边坍缩等局部连接性操作与细分建模。

## 本集主题与目标

上一集已经铺开了几何表示的全景：隐式表示（implicit representation）负责回答"某个点是否在形状内"，显式表示（explicit representation）则直接列出或生成形状上的点，包括点云、多边形网格、等值面等。本集不再泛泛而谈，而是聚焦到最常用的一种显式表示——多边形网格（polygon mesh），把"表面"这个词的确切含义、网格连接性的合法性条件、以及工业级数据结构的设计动机讲清楚。

讲师明确给出了本集的主线假设：处理几何时采用流形假设（manifold assumption）。整集的目标可以拆成三层：第一，建立"曲面 = 局部二维、有内外之分的外壳"这一直觉，并学会辨认非流形（non-manifold）结构；第二，理解为什么值得为网格设计比"一列三角形"更复杂的数据结构；第三，掌握半边结构的最小不变量，并能用它实现若干局部修改操作。结尾点到细分建模（subdivision modeling）与下一集的数字几何处理（digital geometry processing），为后续课程埋下伏笔。

## 核心概念

**流形（manifold）**：直观定义是，在形状上任意一点放大到足够近，都能画出两个独立方向的清晰坐标网格，也就是局部看起来像一张平面。讲师用"从太空看地球是球面，落到曼哈顿能看到街道和大道组成的网格"作类比。它重要的原因是：只有局部二维，才能用二维参数、二维纹理坐标和局部邻域结构去描述表面，算法才不必处理各种维度混乱的奇点。

**非流形（non-manifold）**：存在这样的点，无论怎么放大都画不出二维网格。典型反例是沙漏形（两个锥面在一点相接）、两片表面被"焊接"在一起（交界处可以上下左右移动，还多出一个前后方向，等于三个方向），以及五个多边形共用一条边的"红色星形"。这类结构会让"顶点的邻居有哪些""这条边属于哪个面"变成没有唯一答案的问题。

**扇形与鳍形（fans, not fins）**：讲师给出的记忆口诀，用来判定多边形网格的流形连接性。流形网格里，一个顶点周围的三角形应当排成一圈连续的"扇形"（fan），可以依次编号 1 到 n 再回到 1；非流形顶点则被拆成两个或多个互不相连的扇形，像鱼鳍一样分叉。

**边界（boundary）与带边界的流形**：边界是曲面"结束"的地方，例如裤子的腰线和裤脚。光滑曲面带边界时，局部邻域不是完整圆盘，而是半圆盘（half-disk）；多边形网格里则表现为边界顶点周围是"吃豆人"形状的三角形条带（strip），而不是闭合的三角形环。字幕还强调：所有边界边构成单一的闭合环，这对遍历和修补很有用。

**几何与连接性（geometry vs. connectivity）**：这是全集的隐藏主线。连接性只回答"哪些顶点组成哪个面、哪条边挨着哪个面"，与顶点的 xyz 坐标无关；几何则是这些坐标的实际取值。两者可以独立变化：把立方体的顶点随机挪到乱七八糟的位置，连接性仍然是完美流形，只是面片会自交、翻转。

**三角形汤 / 多边形汤（triangle soup / polygon soup）**：最简单的网格表示，每个三角形单独存三个顶点的坐标，共九个浮点数，三角形之间不共享任何信息。优点是极其简单，而且正是光栅化管线（rasterization pipeline）的天然输入；缺点是顶点被重复存储，且完全无法做邻域查询。

**索引网格 / 邻接表（indexed mesh / adjacency list）**：把网格拆成两个数组，一个是顶点坐标数组，一个是三角形索引数组（每行三个下标）。这一步"把几何与连接性分开"是后续所有数据结构的共同起点。它消除了顶点坐标的重复，但查询"哪些面接触顶点 2"仍要线性扫描整个索引表。

**关联矩阵（incidence matrix）**：用 0/1 矩阵显式记录"顶点—边"和"边—面"的相邻关系。行是边、列是顶点（或行是面、列是边），元素为 1 表示相连。它能以常数时间回答邻域查询，但矩阵规模与网格规模呈二次关系，且修改连接性很麻烦；好处是它天然允许非流形（一行里可以有任意多个 1）。

**稀疏矩阵与压缩列格式（sparse matrix / compressed column, CSC）**：由于绝大多数网格元素互不相邻，矩阵里几乎全是零，没必要存零。可选方案包括用哈希表或树实现的关联数组（查找快、矩阵运算难）、每行一个非零元素链表（插入方便、访问慢且内存跳跃），以及把非零值紧密打包的 CSC（数值数组 + 行索引数组 + 列起始位置数组，矩阵运算高效但修改困难）。实际工程中常先用简单结构建矩阵，再转成 CSC 做计算。

**半边（half-edge）**：把每条无向边拆成两条方向相反的有向半边，作为连接所有网格元素的"胶水"。每个半边记录：孪生半边（twin）、同一多边形内的下一条半边（next）、起点顶点（vertex）、所属边（edge）、所属面（face）。而顶点、边、面各自只存一个指向某条半边的指针。它是本课程大部分时间使用的网格数据结构。

**局部操作**：边翻转（edge flip）交换两个相邻三角形的对角线；边分割（edge split）在边中点插入新顶点，把一个两三角形区域变成四个；边坍缩（edge collapse）把一条边的两个端点合并成一点并删除相关元素。三者都建立在"这条边恰好被两个三角形共享"的简化假设上。

## 关键公式 / 算法 / 数据结构

半边结构的三条基本不变量（讲师用它说明"满足条件的半边集合必然描述一个流形网格"）：

$$
\mathrm{twin}(\mathrm{twin}(h)) = h,\qquad \mathrm{twin}(h) \neq h,\qquad \forall h\ \exists h' : \mathrm{next}(h') = h
$$

即孪生关系是对合（involution）、没有自孪生的边、每条半边都有前驱（next 构成置换，不会出现"链头"）。

面遍历（绕一个多边形走一圈）：

```text
h0 = f.halfEdge; h = h0
repeat:
    visit(h.vertex)      // 或 h.edge、h.face
    h = h.next
until h == h0
```

绕顶点遍历（访问该顶点周围所有出边/三角形）：

```text
h0 = v.halfEdge; h = h0
repeat:
    visit(h)
    h = h.twin.next      // 先孪生再取 next，得到从同一顶点伸出的下一条半边
until h == h0
```

压缩列格式的三个数组（以字幕中的 3×3 例子说明）：`values` 按列优先存放所有非零值；`row_indices` 记录每个值所在的行；`col_ptr` 记录每一列非零元素在 `values` 中的起始/累计位置，第 $j$ 列的范围是 `col_ptr[j]` 到 `col_ptr[j+1]`。查询某列只需按这两个下标切片，无需扫描零元素。

## 讲解脉络

**第一节：从像素方格说起。** 讲师先回顾隐式/显式两大表示，然后突然转向二维图像：为什么数字图像用规则方格，而不是三角形、六边形或不规则铺砌？答案是简单、高效、通用——每个像素四个邻居、易于索引、易于做均值滤波、存储就是一个长数组。但方格也有代价：水平和垂直方向被偏爱，图像采样具有各向异性（anisotropy）。这个"在简单、效率、通用性之间折中"的框架，随后被原样搬到几何上。

**第二节：什么叫表面。** 表面不是实体，而是物体的外壳，像 M&M 巧克力豆的糖衣。表面的关键性质是它是流形：局部可以放二维坐标网格。讲师用地球与曼哈顿作正例，用"中心点无论怎么放大都不变"的锥形相接结构作反例，再让听众判断沙漏、兔子、自折叠物体、环面（torus）中哪些非流形。

**第三节：多边形网格的流形判据。** 因为多边形网格不是光滑曲面，判据可以写得很朴素：每条内部边恰好属于两个多边形；每个顶点恰好属于一个闭合的多边形环（扇形）。随后把边界纳入：边界边只属于一个多边形，边界顶点周围是条带而非环，局部像半圆盘。讲师强调这套假设是为了让数据结构和算法保持简单，避免处理各种粘合异常，而动画与模拟中的常见形状基本都满足。

**第四节：从数组与链表讲起。** 讲师先做"如何存一列数字"的热身：数组支持常数时间随机访问、内存连续、缓存友好，但插入删除困难；链表插入删除容易，但访问要顺着指针走、内存访问零散。他明确说，这两种结构正好对应后面网格数据结构的两大流派。

**第五节：三角形汤 → 索引网格 → 关联矩阵。** 三角形汤是"每个三角形九个浮点数"，简单但冗余、无法做邻域操作。索引网格把顶点坐标和三角形索引分开，第一次实现"几何与连接性分离"，但查"接触顶点 2 的面"仍是线性扫描——大卫像十亿个面时，为了找四个相邻面要扫十亿项，不可接受。于是引入关联矩阵：顶点—边矩阵和边—面矩阵，0/1 编码相邻关系，邻域查询变成查行查列，常数时间；代价是二次规模、修改困难，但能表达非流形。

**第六节：稀疏矩阵。** 既然矩阵几乎全是零，就讨论如何不存零：关联数组（哈希/树）、行链表、压缩列格式。讲师逐一给出优缺点，并指出实际流程常常是"用简单结构构建，再转 CSC 计算"。这一段看似离题，实则铺垫了"网格连接性本质上是稀疏的，需要间接引用"，从而自然引出半边。

**第七节：半边结构与不变量。** 半边是"强化版链表"：每条边拆成两条有向半边，用 twin 和 next 两个指针就能在网格里游走。面只需存一条半边，绕面走 next；顶点只需存一条出边，绕顶点走 `twin.next`。讲师用"你的孪生兄弟的孪生兄弟不是你"这种荒诞对话讲三条不变量，并论证满足不变量的半边集合必然对应流形网格——因此半边"在构造上就无法编码非流形"，这既是限制也是优点。

**第八节：局部操作、结构比较与收尾。** 边翻转只改指针、不增删元素（连续翻转两次可回到原状，但可能存在两套指针表示同一个三角形）；边分割要新增一个顶点、三条边、三个面和一批半边；边坍缩则合并端点并删除元素。随后用三个维度比较邻接表、关联矩阵、半边：能否常数时间访问邻域、能否方便增删元素、能否处理非流形。结论是没有万能结构，多边形汤在纯光栅化场景反而最合适。最后引出细分建模：从一个立方体控制笼（control cage）出发，反复做连接性修改和顶点调整，得到高质量曲面；这也是 Scotty3D 编程作业要实践的内容，并预告下一集的采样、重建与混叠。

## 重点结论

1. 流形假设的本质是"局部二维"：它让曲面可以用二维参数、局部邻域和一致的遍历来描述，是网格算法简洁高效的前提。
2. 多边形网格的流形判据只有两条：每条内部边恰有两个面；每个顶点周围是一个扇形而非多个鳍形。加上边界情形后，边界边只有一个面、边界顶点呈条带。
3. 连接性与几何是两件独立的事。连接性合法的网格，几何可以任意糟糕（自交、翻转、坍缩成一点）；调试时不能凭外观判断连接性对错。
4. 三角形汤简单、通用、是光栅化管线的输入，但冗余且无法邻域查询；索引网格解决了冗余，没解决查询复杂度；关联矩阵解决了查询，却带来二次存储和修改困难。
5. 稀疏性来自"每个元素只与极少数元素相邻"，因此需要哈希、链表或 CSC 这类间接结构；CSC 适合数值计算，不适合频繁修改。
6. 半边用 twin/next 两个核心指针加顶点、边、面引用，把邻域查询降到与局部度数成正比；三条不变量保证它只能描述流形网格。
7. 边翻转、边分割、边坍缩是细分建模与网格简化的原子操作，都依赖"边被两个三角形共享"的假设；把假设放开会显著复杂化实现。
8. 数据结构的选择取决于用途：光栅化用多边形汤，数值计算用稀疏矩阵，交互式编辑与细分用半边。字幕反复强调"从来没有唯一正确的答案"。

- "每个像素都有四个邻居"默认指四邻域（4-connectivity），未讨论八邻域；这不影响论证，但严格说方格网格的邻接定义有多种。
