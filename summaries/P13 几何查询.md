# P13 几何查询

## 一句话概括

本集从"点到点的最近点"这一最朴素的问题出发，逐级构造出点到直线、线段、三角形、三角网格以及隐式曲面的最近点算法，再转向射线与球面、平面、三角形的求交，最后讨论三角形与三角形的相交与连续时间碰撞检测，并指出朴素做法的 $O(n)$ 成本必须靠空间加速结构解决。

## 本集主题与目标

前几集讲的是几何的表示（隐式 implicit 与显式 explicit）以及网格数据结构（半边 half-edge、邻接矩阵、邻接表）。这一集换了一个角度：不再问"几何怎么存"，而是问"几何能回答什么问题"。具体目标包括：

1. 建立一套**由简到繁的构造方法**：把复杂查询拆成已经解决过的原子查询，而不是为每个问题重写新算法。
2. 覆盖最近点查询（closest point query）与相交查询（intersection query）两大类。
3. 对比显式表示与隐式表示在同类查询上的算法差异与权衡。
4. 让听众意识到数值稳健性（numerical robustness）是几何查询的固有难点。
5. 为下一集的空间加速数据结构（spatial acceleration structure）埋伏笔。

讲师反复强调：半边、邻接表这些结构是为"局部邻域"设计的，天生不适合空间查询，因此需要新的思路。

## 核心概念

- **几何查询（geometric query）**：关于两个几何体相对关系的计算，如最近点、距离、是否相交、交点位置、内外判定。它是渲染、动画、几何处理共用的基础操作，因此值得单独抽象出来研究。
- **最近点查询（closest point query）**：给定空间中的查询点 $p$ 和某个几何体，求该几何体上离 $p$ 最近的点。它与"距离查询"等价，因为算出最近点就得到了距离。
- **隐式表示（implicit representation）**：用函数 $f(x)=0$ 定义表面，$f$ 的符号或大小给出内外与距离信息。优点是"点是否在面上/内部"这类测试极其直接；缺点是难以直接枚举表面元素。
- **显式表示（explicit representation）**：用顶点、边、三角形等元素直接列出表面，三角网格是典型例子。优点是便于遍历和渲染；缺点是空间查询需要逐个元素检查。
- **有符号距离场（signed distance field, SDF）**：本集展示的兔子例子中，函数值不只是零/非零，而是给出到表面的距离，离表面越远数值越大（图中由白色过渡到橙色、深红）。它把"表面"变成了一张可插值的标量场。
- **梯度下降式投影**：在隐式距离场上，沿距离梯度的反方向小步移动即可逐步逼近表面。这与显式网格"遍历所有三角形取最小"的算法结构完全不同，是两种表示的核心权衡。
- **射线（ray）**：$r(t)=o+t d$，其中 $o$ 是起点、$d$ 是单位方向、$t\ge 0$。它与"直线"的区别在于有起点、只有半条，因此负的 $t$ 解要被丢弃。
- **奇偶规则（parity test）**：对闭合无孔表面，从内部出发的射线与表面相交奇数次，从外部出发则为偶数次。这是用射线求交做内外测试的巧妙方法。
- **重心坐标（barycentric coordinates）**：把三角形内（及平面上）的点写成三个顶点坐标的加权和，权重和为 1；三个权重全为正即在三角形内部。它把"点在三角形内"变成了一次符号检查。
- **连续碰撞检测（continuous collision detection）**：不只问两个三角形此刻是否相交，而是问在 $t_0$ 到 $t_1$ 之间是否存在某一时刻相交。讲师提示可把时间当作额外维度，三角形随时间扫过的区域近似为"时间棱柱（time prism）"，动态问题就变成高维静态问题。

## 关键公式 / 算法 / 数据结构

**两点距离**

$$d=\sqrt{(a_1-p_1)^2+(a_2-p_2)^2}$$

**点到直线（隐式 $n^\top x=c$，$n$ 为单位法向）**

从 $p$ 沿法向走 $t$ 到达直线：$n^\top(p+t n)=c$，因 $n^\top n=1$ 得

$$t=c-n^\top p,\qquad x^\star=p+(c-n^\top p)\,n$$

**点到线段**

先求所在直线的最近点，再参数化为 $a+t(b-a)$；若 $t\in[0,1]$ 则最近点在段内，否则取较近的端点。伪代码：

```
q = closestPointOnLine(p, a, b)
t = dot(q - a, b - a) / dot(b - a, b - a)
if t < 0: return a
if t > 1: return b
return q
```

**点到三角形（三维）**

1. 把 $p$ 投影到三角形所在平面（与点到平面同一公式，只是二维向量换成三维）；
2. 用三个半空间测试判断投影点是否在三角形内（等价于光栅化器里的内外测试）；
3. 在内部则投影点即答案；否则对三条边分别调用线段最近点，取最小。

**三角网格最近点（朴素算法）**

```
best = +inf
for each triangle T:
    q = closestPointOnTriangle(p, T)
    if dist(p, q) < best: best = dist; answer = q
```

复杂度 $O(n)$，$n$ 为三角形数；上亿面片时不可接受。

**射线与隐式球面**

球面 $f(x)=\|x\|^2-1=0$，代入 $x=o+t d$ 展开：

$$\|d\|^2t^2+2(o\cdot d)t+\|o\|^2-1=0,\quad t=\frac{-b\pm\sqrt{b^2-4ac}}{2a}$$

其中 $a=\|d\|^2,\ b=2o\cdot d,\ c=\|o\|^2-1$。判别式小于零无交，等于零相切，大于零一进一出；负根对应射线反方向，应剔除。

**射线与平面**

$$t=\frac{c-n^\top o}{n^\top d}$$

分母 $n^\top d=0$ 表示射线与平面平行，$t$ 趋于无穷；$t<0$ 表示平面在射线背后。

**射线与三角形**：先求与三角形所在平面的交点，再用有符号面积法或任意重心坐标公式求 $(\alpha,\beta,\gamma)$，三者均非负即命中。

## 讲解脉络

1. **动机：几何处理中的信号退化。** 讲师先回到"网格反复降采样、升采样、细分后形状逐渐走样"的现象，提出把新网格顶点投影回原始表面以保住原信号。这把一个宏大的应用问题压缩成"给定点，找表面最近点"。
2. **提出问题的层级。** 接着连续发问：用隐式还是显式？用半边还是邻接矩阵？朴素成本多少？并指出数据结构不是主要矛盾，真正的难点在查询本身。
3. **从零维到二维的构造。** 点到点（显然）、点到直线（沿法向走 $t$）、点到线段（先直线再夹到 $[0,1]$）、点到二维三角形（内部则自身，否则三条边取最小）。这一段刻意慢，目的是让"分解成子问题"的方法论被看清。
4. **升到三维。** 三维三角形无法直接套二维，于是先投影到平面，再做半空间测试；并强调平面与直线公式完全同构，只差向量维数。
5. **网格最近点与复杂度。** 遍历所有三角形取最小，$O(n)$；讲师明确说本集不优化，下一集才讲加速。
6. **换到隐式表示。** 用距离场兔子说明 $f$ 携带距离信息，算法改为从查询点沿负梯度迭代走向表面；随后提出"是否干脆把最近点也预存下来"的内存/速度权衡。
7. **转向相交查询。** 定义射线，讲奇偶内外测试、阴影可见性、碰撞检测三种用途；推导射线与球面（二次方程三种解对应穿过、相切、擦肩）、射线与平面（平行与负 $t$ 两种退化）。
8. **射线与三角形、三角形与三角形。** 平面交点 + 重心坐标；三角形相交则化为"每条边是否穿过对方三角形"，即射线—平面 + 区间测试 + 内外测试。最后提出连续时间版本，用时间作额外维度，并预告高维二分查找式的加速结构。

## 重点结论

- 几何查询的价值在于**复用**：射线—三角形测试内部就是"射线—平面 + 点在三角形内"，而后者正是光栅化器早就在做的事。
- 显式与隐式不是风格差异，而是**算法结构差异**：显式是"枚举 + 取最小"的全局搜索，隐式是"用局部梯度信息迭代"的爬坡。
- 射线与球面的二次方程的解的个数、符号，直接对应穿过、相切、未命中、命中在背后四种几何情形；解方程本身就在传递几何信息。
- 朴素最近点与朴素求交都是 $O(n)$，面对百万至十亿级面片不可行；这是下一集存在的理由。
- 数值稳健性是几何查询的固有组成部分。两条接近平行的直线，法向的微小扰动会让交点剧烈跳动，浮点精度（约 7 位或 16 位有效数字）不足以"照公式算"。
- 优化射线—三角形相交不是学术洁癖：皮克斯单帧约需 50 小时计算，还要每秒 4 帧连续渲染，因此 Intel 的 Embree、NVIDIA 的 OptiX 与 RTX 硬件管线长期投入这一条查询。

## 字幕含糊或可能有误的地方

- "n转置p加上t转置n等于c"——应为 $n^\top p+t\,n^\top n=c$，其中 $t$ 是标量而非向量，不存在"$t$ 转置"。
- "NVIDIA 创建了名为 Optics 的库"——应为 **OptiX**，GPU 光线追踪库；"Bri"应为 **Embree**（Intel 的 CPU 光线追踪库）。
- "Project Soul"——NVIDIA 的实时光追演示，名称音译可疑，常见写法为 **Project Sol**；讲师也说明它是光栅化与光追的混合，并非纯光追。
- "数组排列"“所有点 x 沿数组排列”——应为"沿射线排列（along the ray）"，是 ray 被误听成 array。
- "计算机仅有二三十位或六十四位精度"——应是单精度约 24 位有效二进制位、双精度约 53 位（常说 32/64 位浮点），表述含混。
- "这被称为 Project Soul 实际上这个我首先要说明的是这并不完全确定光线追踪"——语义断裂，应为"这并不完全是光线追踪"。
- "连衣裙的某部分是否撞到了另一部分"一段中"实现某种接触响应"与前文"碰撞检测"混用，属口语重复，不影响理解。
